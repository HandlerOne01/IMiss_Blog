> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 删掉「排行」模块，用 `/roadmap/` 单页把站内 133 篇笔记组织成 **8 条主线 × 阶段** 的学习路线（纯静态、零新素材）。

**Architecture:** 数据（`roadmapConfig`）与解析（`roadmap-utils` 纯函数）分离，页面只做"取数 + 渲染"；**解析失败在构建期抛错**（不许渲染死链）；导航第 3 格「排行」→「学习路线」；排行的页面 / 配置 / 组件 / 样式 / 演示图 / 44 条断言 / 文档整条删除。

**Tech Stack:** Astro 7（`getCollection` + `render` 取阅读时长）、**不用 Svelte**（纯静态）、页面级 CSS、零依赖 CDP 断言脚本（`scripts/verify-ui.mjs`）。

**Spec:** `prd.md` **§3.5R**（需求 R-PATH-01~06）+ `ARCH.md` **§5**（设计与文件清单）。两份都已提交（`7f0fb26`）。

## Global Constraints

- 包管理器只能是 **pnpm**；Node ≥ 22（`preinstall` 会拦）。
- 站点是**静态输出**，**用户可见内容不许依赖 JS**（`prd.md` §6.2）—— 路线页必须是纯静态 HTML。
- 代码风格：`src/` 走 Biome（tab 缩进、双引号）；`scripts/` 不 lint 但**参与 `tsc --noEmit`**。
- **三张表规则**：任何改动都要同步 `prd.md` / `ARCH.md` / `PROJECT_STATUS.md`，三份共用同一版本号；改完必跑 `pnpm verify:docs`。
- 改断言后跑 `node reports/sync-doc-counts.mjs --write`（它从 `reports/verify-ui.log` 同步"断言 N 项 / 截图 N 张"）。
- **验证环境三条陷阱（`ARCH.md` §14.3 T71~T73）**：① 服务**不跨进程继承**，动手前自己拉起 `langgraph dev --port 2024`（`cd ..\agent_-for_-blog; .venv\Scripts\langgraph.exe dev --port 2024 --no-browser`）与 `pnpm preview --port 4323`；② 受限沙箱下 `astro preview` / `astro sync` 会以 `Unable to load your Astro config / require is not defined` 失败（**不是代码坏了**）；③ `verify:ui` 默认打 **4321**（别人的 dev server），本计划一律用 `node scripts/verify-ui.mjs --base http://localhost:4323`。
- **明确不做**（发起人 2026-09-27 选定）：localStorage 进度打勾、「下一站」、拖拽排序、8 个子页面、每篇 note、轻量行封面图、`/rank/*` 的 301。
- **⛔ 不要跑 `pnpm lint` / `pnpm format`**（Task 2 实测事故）：这两个脚本是 `biome check|format --write ./src ./scripts`，而 `scripts/` 里有 **CDP 采集器的模板字符串**（`COLLECT` 内嵌正则）—— Biome 的 `--write` 会把 `/rgba?\(([^)]+)\)/` 改写成 `/rgba?(([^)]+))/`（**语义已变**），并顺带重排 19 个与本任务无关的文件（1761 行）。本项目**没有**"提交前必须 lint"的规矩；要保格式就跑 **`npx biome check src/types/roadmapConfig.ts src/config/roadmapConfig.ts src/utils/roadmap-utils.ts`**（只针对动的文件、且只检查不写）。
- 8 条线的顺序与篇目**以 Task 1 的数据为准**；改顺序必须同步 `ARCH.md` §5.3 那张表。
- 断言口径：**257 → 229**（删 44 条 R-RANK，其中 **10 条通用判据迁移**到路线页、**34 条排行专属删除**；新增 **16 条** R-PATH）。本计划里 16 条的分布：T2 六条、T3 两条、T4 两条、T5 六条。

## Review Focus

1. **同名篇目**（`cpp` 与 `stl` 下都有 `vector` / `list` / `string`）—— 显示名与跳转必须**成对定位**，错配会静默指到另一篇。→ Task 1 的红绿实验 + Task 2 断言 #4。
2. **文章被改名或分类被删** —— 路线页必须**构建期失败**，不许渲染出死链。→ Task 1 Step 6 的"故意写错"实验。
3. **锚点稳定性** —— 中文标题不能用序号当 id；锚点要在 Swup 切页后仍可用。→ Task 2 断言 #2 + Task 5 断言 #14。
4. **一页 133 行的体积与构建耗时** —— 轻量行**不许出现 `<img>`**（防以后有人加封面把首屏拖爆）；`render()` 133 篇的构建增量 **> 15 秒**必须走退路。→ Task 2 断言 #6 + Step 7 实测。
5. **无 JS / 打印 / 390px** —— 内容必须全在（不许靠 JS 补），打印也要完整。→ Task 5。

```ts
// src/types/roadmapConfig.ts
/** 难度档：只用于页面上的一个标签，不参与任何逻辑 */
export type RoadmapLevel = "入门" | "进阶" | "实战";

export interface RoadmapStop {
	/** 分类目录名（对应 `src/content/posts/<category>/`）—— **必须与 slug 成对**：
	 *  站内 `cpp` 与 `stl` 下都有 `vector` / `list` / `string`，只按 slug 查会命中错的那篇。 */
	category: string;
	slug: string;
	/** 只覆盖本页显示名（如「vector · 用法」），**不改文章标题、不影响 URL** */
	name?: string;
	/** 跨线复用：同一篇出现在多条线里（全站限 2~3 处） */
	crossLine?: boolean;
}

export interface RoadmapStage {
	/** 阶段标题（页面上是 h3） */
	title: string;
	stops: RoadmapStop[];
}

export interface RoadmapLine {
	/** 锚点用（`#line-<id>`）——**不许用序号当 id**，改顺序时锚点不能失效 */
	id: string;
	name: string;
	/** 一句话说明：这条线在讲什么、读完能干什么 */
	summary: string;
	level: RoadmapLevel;
	stages: RoadmapStage[];
}

export interface RoadmapConfig {
	lines: RoadmapLine[];
}
```

```ts
// src/utils/roadmap-utils.ts
import type { RoadmapConfig } from "../types/roadmapConfig";

/** 页面侧传进来的最小文章信息（由 `getCollection` + `render` 组装） */
export interface PostLite {
	category: string;
	slug: string;
	title: string;
	minutes: number;
}

export interface ResolvedStop extends PostLite {
	/** 显示名：`name` 覆盖优先，否则用文章标题 */
	display: string;
	href: string;
	crossLine: boolean;
}
export interface ResolvedStage {
	title: string;
	stops: ResolvedStop[];
}
export interface ResolvedLine {
	id: string;
	name: string;
	summary: string;
	level: string;
	stages: ResolvedStage[];
	/** 本线停靠点数（含跨线站） */
	stopCount: number;
	/** 本线总时长（分钟，含跨线站） */
	minutes: number;
}
export interface ResolvedRoadmap {
	lines: ResolvedLine[];
	/** 停靠点总数（含跨线，重复计数） */
	stops: number;
	/** 并集篇数 —— **必须等于站内文章数**（R-PATH-04 的命根子） */
	unique: number;
	totalMinutes: number;
	crossCount: number;
}

/**
 * 把配置解析成可渲染结构。**找不到文章就抛错**（R-PATH-04）：
 * 构建期失败远好过渲染出一条死链 —— 这是"改了文章 slug 之后路线页必须报错"的实现基础。
 * 纯函数：不碰 astro:content、不读文件，所以能在 `npx tsx` 里直接测（见 reports/_roadmap-check.mts）。
 */
export function resolveRoadmap(
	cfg: RoadmapConfig,
	posts: PostLite[],
): ResolvedRoadmap {
	const byKey = new Map<string, PostLite>();
	for (const p of posts) byKey.set(`${p.category}/${p.slug}`, p);

	const missing: string[] = [];
	const seen = new Set<string>();
	let stops = 0;
	let totalMinutes = 0;
	let crossCount = 0;

	const lines: ResolvedLine[] = cfg.lines.map((line) => {
		const stages: ResolvedStage[] = line.stages
			.map((stage) => {
				const resolved: ResolvedStop[] = [];
				for (const stop of stage.stops) {
					const key = `${stop.category}/${stop.slug}`;
					const post = byKey.get(key);
					if (!post) {
						missing.push(key);
						continue;
					}
					seen.add(key);
					stops += 1;
					totalMinutes += post.minutes;
					if (stop.crossLine) crossCount += 1;
					resolved.push({
						...post,
						display: stop.name ?? post.title,
						href: `/posts/${post.category}/${post.slug}/`,
						crossLine: Boolean(stop.crossLine),
					});
				}
				if (resolved.length === 0)
					console.warn(`[roadmap] 「${line.name} / ${stage.title}」阶段里一篇都没有，已跳过`);
				return { title: stage.title, stops: resolved };
			})
			.filter((stage) => stage.stops.length > 0); // 空阶段不渲染（ARCH §5.6）
		return {
			id: line.id,
			name: line.name,
			summary: line.summary,
			level: line.level,
			stages,
			stopCount: stages.reduce((n, st) => n + st.stops.length, 0),
			minutes: stages.reduce(
				(n, st) => n + st.stops.reduce((m, s) => m + s.minutes, 0),
				0,
			),
		};
	});

	if (missing.length > 0) {
		throw new Error(
			`[roadmap] 有 ${missing.length} 个篇目在站内找不到（category/slug 必须成对且真实存在）：${missing.join(", ")}`,
		);
	}
	// 空线 / 空阶段直接丢掉（ARCH §5.6），并留下构建日志
	const kept = lines.filter((line) => {
		const ok = line.stopCount > 0;
		if (!ok) console.warn(`[roadmap] 主线「${line.name}」一篇都没有，已跳过`);
		return ok;
	});
	return { lines: kept, stops, unique: seen.size, totalMinutes, crossCount };
}
```
