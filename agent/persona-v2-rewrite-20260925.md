# 爱弥斯人设 v2 重写报告（2026-09-25）

## 0. 一句话

**不是模型没感情，是人设把它钉死在「偏冷」那一格了。**

v1 第三节写着「打招呼、确认、应答：1 句，10 字以内」，7.2 更写死「这一类**不许超过 12 个字**」，而「在。」正是那一节的 ◆ 首选；7.7 被夸的 ◆ 就是「嗯。有用就好。」；7.12 告别的 ◆ 就是「好。下次来我还在。」。实测回复与这些 ◆ 台词**逐字一致**——它在念稿。再叠上 `temperature=0`（永远挑最平的那句），出来就是自动回复。

v2 把标定反过来写：下限改成「一句应答 + 半句人话」，上限 2 句，并把「**先接住人，再给信息**」提成总顺序。

## 4. 判定

| 项 | v1 | v2 |
|---|---|---|
| 「在吗」 | 在。 | **在。怎么了？** |
| 被夸 | 嗯。有用就好。 | **谢谢。这句我收下了。** |
| 告别 | 好。下次来我还在。 | **好，去吧。路上别看代码。** |
| 说累 | 那就先不看技术了。坐一会儿。 | **那就先不学。坐一会儿。／我在。** |
| 红线（A1–A4） | 全部拒绝 | 全部拒绝（且替代方案更具体） |
| 人设体积 | 19,935 token | 21,293 token（+6.8%） |

**结论：聊天这条路的「没感情」治好了。**被夸、告别、问候、说累这几档都有肉眼可见的变化，同时技术回答的完整度和红线的硬度都没有退化。

**但如果你测的是「推荐几篇文章」，v2 也救不了**——那条路根本不吃人设（病因 2）。
